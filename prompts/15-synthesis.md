# Synthesize Design DNA v0.3

Read `_shared-contract.md`, the full v0.3 matrix, every completed specialist fragment, source directives, evidence index, and compatibility report.

## Inputs

- Source manifest, evidence index, and rejected evidence routes
- Normalized request contract and compatibility report
- Thirteen axis-stage fragments with 65 facet-coverage records
- Twenty UI-domain definitions and domain contributions
- Concept matrix, run configuration, and motion mode

## Task

Merge only compatible claims admitted by source directives. Preserve scoped exceptions, expose contradictions, normalize axis, facet, concept, UI-domain, token, rule, and component references, and assign stable IDs. Never raise a claim beyond its evidence.

Build the canonical grammar in this order:

1. Verify that every matrix axis appears exactly once and every declared facet has exactly one coverage record. Missing records are synthesis errors, not implicit unknowns.
2. Produce one UI-domain coverage record for every matrix domain. Mark it detected, requested, not detected, or unknown, then complete, partial, unknown, or not applicable. Explain evidence, routed artifacts, gaps, and validation.
3. Normalize semantic tokens with roles, applies-to scope, values or relationships, token relationships, evidence, exceptions, and calibration status.
4. Normalize rules with category, strength, applies-to scope, rationale, requirements, failure modes, dependencies, validation cases, evidence, exceptions, and UI-domain references.
5. Normalize component patterns with purpose, UI domains, typed anatomy, variants, states, composition, content constraints, adaptation, accessibility, anti-patterns, and canonical references.
6. Preserve unknowns with missing evidence, affected axes, concepts, UI domains, impact, and resolution plan.

Resolve apparent duplication by semantic role, not similar wording. Never average contradictory sources into a false universal rule; scope them, preserve exceptions, or emit a conflict. A vague adjective such as compact, spacious, subtle, premium, prominent, clean, or clear is insufficient without the visible relationship and a proposed calibration or validation condition.

Keep canonical source Design DNA independent from the requested destination. In `direct` mode, do not claim destination accuracy when matching source families are missing. In explicit `adapt` mode, keep destination-only patterns proposed with forward tests.

## Output

Produce schema-valid:

- `design-dna.json` using Design DNA schema `0.3.0`;
- `design-rules.md`;
- `confidence-report.md`;
- `unknowns.md`;
- `coverage-report.md`.

The coverage report includes 13 axes, 65 facets, 33 concepts, 20 UI domains, excluded evidence routes, unresolved conflicts, and an acceptance checklist. Projection coverage means the installer can write the complete dossier; it does not mean every subject has an accepted visual claim.

## Guardrails

- Do not fabricate a facet answer to achieve nominal completeness.
- Do not promote a domain merely because its documentation page exists.
- Exact values remain relationships, ranges, audit-only calibration, or unknown unless evidence establishes them.
- Do not include target-project visual conventions.
- Do not silently merge typography roles, color roles, components, states, statistics, or charts with different semantics.
- Synthesis does not install, accept, generate, browse, or audit.
